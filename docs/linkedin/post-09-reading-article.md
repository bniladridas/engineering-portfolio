We are taught to write code, rarely to read it. But reading is most of the job.

For every hour I spend writing code, I spend several reading it — mine from last month, someone else's from three teams ago. No one ever taught me how. It's a craft, and it can be learned deliberately.

*Reading Code With Intention* is up. The habits that work:

- Read from behavior inward, following the call graph as a map — not top to bottom like prose.
- Read the tests first. They're the most honest documentation a codebase has.
- When you're surprised, ask if the behavior is complex or the shape is gratuitously novel. Usually the second.
- Debugging is reading under pressure: one hypothesis at a time, tested cheaply.
