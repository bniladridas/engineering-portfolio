A refactor is a letter to the next engineer. Every rename, every extracted function, every deleted comment is a sentence in it.

I used to see refactoring as mechanical: improving structure without changing behavior. Technically correct, practically incomplete.

Structure *is* the documentation. The best refactors remove the need for explanation.

New article, *Refactoring As Communication*:

- Names are the highest-value documentation. If a function needs its body explained, it needs a new name.
- Extraction turns a wall into a map. If you can name a chunk, it deserves to be a function.
- Deletion is honesty: dead code and stale comments are noise.

The sustainable form is continuous, not the big-bang rewrite. Small improvements, every change.
