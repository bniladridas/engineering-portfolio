Developers don't adopt tools because they're powerful. They adopt tools that let them stay in flow. Everything else is a tax.

A developer's most expensive asset is concentration. It takes twenty minutes to build and one confusing error message to destroy.

In *Developer Tools That People Remember*, I wrote about what separates the tools that endure:

- Errors are the interface. Answer four questions: what, where, what to do, what happens if you don't.
- Defaults are opinions. Conservative defaults fail safe and never surprise.
- Delight lives in the details: dry-run flags, honest progress bars, help that helps.
- A tool is judged by the work it removes from a day, not the features it adds.
