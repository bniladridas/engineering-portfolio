Every design meeting asks: what should this system look like?

The useful question is rarely asked: what should this system *become*? Systems are never finished. They are changed, extended, and repaired. The only design goal that matters is making those changes safe and cheap.

In *Designing Maintainable Systems*, I wrote about the shape that survives:

- Put boundaries where volatility lives — the seam is where change gets absorbed.
- Couple to stable things: interfaces, contracts, data shapes.
- Predictable beats clever. Novelty is the enemy of maintainability.
- Write the one-page design note while the decision is fresh.

The system designed to be improved is the system that will be.
